# Ruxir's Dotfiles

Personal Linux desktop and terminal configuration, managed with
[GNU Stow](https://www.gnu.org/software/stow/).

This repository is laid out as a Stow package rooted at the home directory.
Files in this repo mirror where they should live under `$HOME`. For example:

- `.zshrc` becomes `~/.zshrc`
- `.config/kitty/kitty.conf` becomes `~/.config/kitty/kitty.conf`
- `.config/hypr/hyprland.conf` becomes `~/.config/hypr/hyprland.conf`

GNU Stow then creates symlinks from `$HOME` back into this checkout, so edits
made in the real config paths are edits to this repository.

## What's Included

This setup currently covers shell, terminal, editor, desktop, and theme files,
including:

- shell startup files for Zsh, Bash, Fish, and profile setup
- Git, GTK, Qt, MIME, Xresources, and desktop environment config
- Hyprland, Niri, Waybar, Fuzzel, Rofi, and systemd user services
- Kitty, Ghostty, Alacritty, Btop, Cava, Flameshot, and Fastfetch
- Neovim, Doom Emacs, Helix, Micro, Lazygit, Lazydocker, and Zed
- theme assets under `.themes/`, Kvantum, GTK, and terminal color files

## Install On A New Machine

Install Git and GNU Stow first.

Arch/CachyOS:

```sh
sudo pacman -S git stow
```

Clone the repo into your home directory:

```sh
git clone git@github.com:ruxir-ig/dotfiles.git ~/dotfiles
cd ~/dotfiles
```

Preview what Stow would link:

```sh
stow --target="$HOME" --simulate --verbose .
```

Apply the symlinks:

```sh
stow --target="$HOME" --verbose .
```

If Stow reports conflicts, it means a real file already exists where a symlink
would go. Move that file out of the way, compare it with the repo version, then
run the command again.

## Daily Workflow

After Stow is applied, edit files normally from their home locations:

```sh
nvim ~/.zshrc
nvim ~/.config/hypr/hyprland.conf
nvim ~/.config/kitty/kitty.conf
```

Because those paths are symlinks into `~/dotfiles`, Git will see the changes:

```sh
cd ~/dotfiles
git status
git add -A
git commit -m "update dotfiles"
git push
```

## Uninstall Or Relink

Remove the symlinks created by Stow:

```sh
cd ~/dotfiles
stow --target="$HOME" --delete .
```

Re-apply them later:

```sh
stow --target="$HOME" .
```

## Notes

- `.stow-local-ignore` keeps repository metadata and docs from being linked
  into `$HOME`.
- `.gitignore` excludes generated caches and runtime state that should not be
  versioned.
- The Helix runtime grammar cache is intentionally ignored because it contains
  many nested Git repositories generated by Helix.
- Some files are machine-specific. Review service files, paths, secrets, and
  hardware-specific settings before using this repo on another machine.
